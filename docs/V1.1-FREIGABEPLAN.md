# V1.1 – Plan: Veröffentlichung auf GitHub Pages und iPhone-Praxistest

## A. Voraussetzungen (erfüllt)
Live-Smoke-Test bestanden · Tests 73/73 · Upgrade-Prüfung bestanden · Repo-Prüfung sauber (siehe `docs/TESTBERICHT.md`).

## B. Veröffentlichung (nur nach Freigabe durch den Nutzer)
1. **Vorher lokal aufräumen** (verhindert, dass der alte Name je veröffentlicht wird): `git branch -D archiv-nicht-pushen`, dann `git reflog expire --expire=now --all && git gc --prune=now`. Danach darf `git log --all` den Namen nicht mehr enthalten.
2. **Nie** `git push --all`/`--mirror` verwenden; nur den Branch `feature/v1.1` gezielt pushen: `git push -u origin feature/v1.1`.
3. **Pull Request** `feature/v1.1 → main` öffnen (Beschreibung: Funktionen, Testbericht, Rückfallplan). Die Pages-Aktion läuft erst beim Merge nach `main`.
4. **Merge nach `main`** (erst nach ausdrücklicher Freigabe) → die Aktion baut `dist/` und veröffentlicht `https://lotoco-lab.github.io/mathe-trainer/`. Dauer ca. 1 Minute.
5. **Prüfung nach dem Deploy** (Claude, ohne Zugangsdaten): Startseite, `eltern.html`, `sw.js`, Manifest, Icons, `config.js` per HTTPS abrufbar; Precache-Liste vollständig; Build-ID neu; keine Treffer für Name/Secrets im ausgelieferten Code.
6. **Rückfall:** `git revert` des Merge-Commits → Pages liefert wieder V1.0. Lokale Daten bleiben nutzbar (V1.0 nutzt `mathe.progress.v1` weiter; neue Schlüssel stören nicht, Sicherung `mathe.backup.v1.0` bleibt). Cloud-Daten bleiben in Supabase.

## C. iPhone-Praxistest (Nutzer, ca. 20–30 Minuten; Claude wertet Rückmeldungen aus)
| # | Schritt | Erwartung |
|---|---|---|
| 1 | App vom Home-Bildschirm öffnen, schließen (App-Umschalter wegwischen), erneut öffnen, nochmal | Beim 1. Öffnen evtl. noch alte Version, danach neue (Startseite zeigt „⚙︎ Eltern“; Version unter „Mein Fortschritt“) |
| 2 | Alte Sterne, Stufe und „Knifflige Aufgaben“ prüfen | Wie vor dem Update |
| 3 | Mac/iPhone: `…/eltern.html` öffnen, anmelden, „Kind-Gerät koppeln“ | 8-stelliger Code erscheint |
| 4 | Kind-iPhone: ⚙︎ Eltern → Code → Koppeln | Status „Gekoppelt“ |
| 5 | 5 Aufgaben rechnen, ⏸ Pause, ⚙︎ → „Jetzt sichern“ | Elternseite (Aktualisieren) zeigt Einheit „unterbrochen“, 5/50 |
| 6 | Flugmodus an, weiter üben (Fortsetzen, 5 Aufgaben), Flugmodus aus, App offen lassen | Nach kurzer Zeit „☁︎ Gesichert“, Elternseite zeigt 10/50, keine Dublette |
| 7 | App mitten in einer Aufgabe über den App-Umschalter beenden, neu öffnen | „Weiter üben“ vorhanden, gleiche Aufgabe |
| 8 | Eine ganze Einheit (50) beenden, dabei absichtlich 2 Fehler | Wiederholungsrunde „zählt nicht mit“, Ergebnisseite, Elternansicht zeigt Fehlerarten und Details |
| 9 | Elternseite: Export CSV/JSON, Gerät trennen (nur Testdaten!) | Dateien laden; Gerät „getrennt“, Kind-App meldet „Kopplung beendet“, rechnet weiter |
| 10 | Touch-Eindruck: Tastengröße, Lesbarkeit, Sicherheitsabstände (Notch/Home-Balken), Elternseite auf dem iPhone | Notieren, was stört |
Abnahme: Schritte 1–9 wie erwartet, keine Datenverluste. Danach echte Nutzung; Löschen der Testeinheiten über die Elternseite.

## D. Freigabeempfehlung und Restrisiken
**Empfehlung: Freigabe zur Veröffentlichung, sobald B.1 erledigt ist.** Alles automatisch Prüfbare ist bestanden, die Cloud-Seite ist live geprüft.
Restrisiken: (1) iOS-Verhalten des Updates und der Synchronisierung nur per Praxistest (Plan C); (2) Free-Plan pausiert bei einer Woche ohne Aktivität (Kind-App rechnet weiter, Sync holt nach; Projekt im Dashboard wieder starten); (3) Eltern-Konto nur mit Passwort (kein MFA) – starkes, nur dort verwendetes Passwort, Elternseite speichert nichts; (4) das Kind-Gerät hält ein Schreib-Token (Eltern können trennen); (5) Safari löscht Website-Daten ungenutzter Seiten – die installierte App ist davon ausgenommen, die Cloud-Sicherung dient als Rückhalt; (6) CORS ist vorab per Anfrage bestätigt, der echte Browser-Aufruf von der Pages-Adresse wird erstmals in Plan C geprüft.
