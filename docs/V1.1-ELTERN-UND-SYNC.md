# V1.1 – Einrichtung, Kopplung, Elternübersicht, Migration

Status: **lokal entwickelt und getestet, noch nicht veröffentlicht, keine Cloud-Ressource angelegt.**

## 1. Einmalige Einrichtung (nach Freigabe)
1. **Supabase-Konto/Projekt** anlegen (https://supabase.com, Free-Plan), Region **Central EU (Frankfurt)**. Datenbank-Passwort im Passwortmanager ablegen (niemals ins Repo).
2. **SQL Editor** → Inhalt von `supabase/schema.sql` einfügen und ausführen. Danach in „Database → Functions“ prüfen, dass fünf Funktionen existieren.
3. **Authentication → Sign In / Providers → Email**: „Allow new users to sign up“ **ausschalten**. Unter **Authentication → Users → Add user** das Eltern-Konto mit E-Mail und starkem Passwort anlegen (Auto-Confirm).
4. **Project Settings → API**: *Project URL* und *anon public key* kopieren (der `service_role`-Schlüssel wird nie benötigt!) und in `src/js/config.js` eintragen. Beide Werte sind öffentlich gedacht.
5. Testen, dann veröffentlichen (siehe 6).

## 2. Kind-Gerät koppeln
1. Eltern öffnen `https://lotoco-lab.github.io/mathe-trainer/eltern.html` (Mac oder iPhone) und melden sich an.
2. **„Kind-Gerät koppeln“** zeigt einen 8-stelligen Code (10 Minuten gültig, einmalig).
3. Auf dem Kind-iPhone: App → unten **⚙︎ Eltern** → Code eingeben → **Koppeln**. Danach erscheint „☁︎ Gesichert“ auf dem Startbildschirm.
4. Trennen: in der Elternübersicht „Trennen“ beim Gerät, oder in der Kind-App „Kopplung lösen“ (mit Elternfrage).

## 3. Was die Elternübersicht zeigt
- Kacheln: Übungen, abgeschlossen/offen, Aufgaben, Quote im ersten Versuch, Hilfestellungen.
- **Entwicklung**: Linie „richtig im ersten Versuch“ je Übung (einfache SVG-Grafik, keine Bibliothek).
- **Häufige Fehlerarten**: Rechenzeichen verwechselt, Nachbaraufgabe im Einmaleins, Zehner-/Einer-/Hunderterfehler, Ziffern vertauscht, sonstige; dazu die schwächsten Rechenarten/Stufen.
- **Letzte Übungen** mit Datum/Uhrzeit, Rechenart, Stufe, bearbeiteten Aufgaben, Quote, Hilfen, Status. Klick auf eine Zeile öffnet die **Detailansicht** mit jeder Aufgabe, dem richtigen Ergebnis, allen abgegebenen Antworten, Versuchen und Zeitpunkt.
- Export (JSON, CSV), Geräteliste, „Alle Lerndaten löschen“.

## 4. Was gespeichert wird
Je Übung: zufällige ID, Start/letzte Aktivität/Abschluss (UTC), Rechenart, Stufe, Zähler (bearbeitet, 1. Versuch, 2. Versuch, Hilfen, offen), Status (aktiv/unterbrochen/abgeschlossen). Je Aufgabe: Aufgabe, Ergebnis, Antworten, Versuche, Hilfe ja/nein, Zeitpunkt, Phase. **Keine** Namen, Standorte, Gerätekennungen oder Tracker.
Lokal: `mathe.s.<id>` (Datensätze), `mathe.active.v1` (Zwischenstand), `mathe.sync.v1` (Kopplung/Bestätigungen), `mathe.progress.v1` (Sterne/Knifflige – wie V1.0).

## 5. Verhalten der Übungseinheit
- **Genau 50 bewertete Aufgaben.** Bis zu 5 davon sind knifflige Aufgaben aus früheren Übungen (Kennzeichnung „🔁 Aus früheren Übungen“, zählen mit).
- Danach folgt eine **zusätzliche, unbewertete Wiederholungsrunde** (höchstens 10 der verfehlten Aufgaben, Kennzeichnung „Wiederholung – zählt nicht mit“). Weitere verfehlte Aufgaben bleiben in der Liste „Knifflige Aufgaben“.
- **⏸ Pause** speichert den Stand; auf dem Startbildschirm erscheint „Weiter üben (18/50)“. Jede abgegebene Antwort wird sofort lokal gespeichert, auch bei App-Beendigung.

## 6. Veröffentlichung (erst nach Ihrer Freigabe)
Merge von `feature/v1.1` nach `main` → GitHub Pages baut automatisch. Vorher einmal lokal mit `python3 tools/test.py` und mit dem echten Supabase-Projekt den Smoke-Test aus Abschnitt 8 durchführen.

## 7. Update und Migration von V1.0
- Der V1.0-Fortschritt (`mathe.progress.v1`) bleibt unverändert nutzbar. Beim ersten Start von V1.1 wird eine **Sicherung** `mathe.backup.v1.0` angelegt und `mathe.meta` (Schema 2) gesetzt. Ist der Fortschritt später unlesbar, wird die Sicherung automatisch zurückgespielt.
- Neue Daten liegen in eigenen Schlüsseln; eine ältere App-Version kann sie daher nicht überschreiben.
- Die bestehende iPhone-Installation wird weiterverwendet. Der Service Worker aktualisiert sich selbst (neuer Cache, alter wird gelöscht); die Seite lädt nur auf dem Startbildschirm neu, nie mitten in einer Übung.

## 8. Smoke-Test mit dem echten Dienst (nach Einrichtung)
Elternseite anmelden → Code erzeugen → Kind-App koppeln → 3 Aufgaben lösen → „⚙︎ → Jetzt sichern“ → Übung erscheint in der Elternübersicht → Flugmodus, weiter üben, Flugmodus aus → Stand wird nachgetragen → Elternseite: Export, danach „Alle Lerndaten löschen“ (Geräte werden getrennt).

## 9. Ehrliche Einschränkungen der Prüfung
- `supabase/schema.sql` wurde **nicht gegen eine echte PostgreSQL/Supabase-Instanz ausgeführt** (keine Cloud-Ressource ohne Freigabe, lokal kein Postgres). Die automatischen Tests laufen gegen einen Nachbau der Regeln im Testserver (`tools/test.py`). Sorgfältiges Lesen ersetzt den Smoke-Test aus Abschnitt 8 nicht.
- Verhalten von Safari/iOS (Installation, Hintergrund, Speicher) ist nur auf dem iPhone prüfbar.
